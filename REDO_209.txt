WHAT HAPPENED
These 209 are one unbroken run of notes in the collection —
word_mãnh through word_ngơi, rows 4527-4735 of AllViet_MASTER.csv.
Their male field was never regenerated with NamMinh; it still points
at a clip from an earlier female HyperTTS run. The notes on either
side of the run (word_mánh before, word_ngợi after) are correct, so
this was a single batch that got skipped, not a scattered failure.

HOW I FOUND THEM
Every file in the batch encodes at 24000 Hz / 96 kbps except these,
which are 22050 Hz / 56 kbps — a different engine. That split is a
clean binary with no borderline cases, and it matched the one file
you identified by ear (word_mãnh).

Pitch was NOT used. Calibrating it on these 209 against 250 known-good
single-word clips gave medians of 168 Hz vs 133 Hz but distributions
that overlap by more than half — 72% of the male clips sit above the
female 5th percentile. In a tonal language, F0 on an isolated syllable
is mostly the tone, not the speaker. It cannot identify a voice here.

HOW TO FIX

2. Select all. CLEAR Vietnamese_Male_Sound first —
   Notes > Find and Replace, field Vietnamese_Male_Sound,

   replace with nothing. HyperTTS skips notes that already have
   audio, which is why this batch was missed.
3. Run HyperTTS on the selection with the same Azure NamMinh voice.
4. Export the deck again and tell me. I will re-verify by profile.
